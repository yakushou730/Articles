模型（The Model）

16 個條目

AI

一個會移動的標籤，不是一項技術。它指向電腦當下能做、而且令人印象深刻的新事情，目前是大型語言模型（large language models）。

模型（Model）

參數本身。無狀態，只做下一 token 預測，別無其他。單靠自己做不到任何代理式（agentic）的事。

參數（Parameters）

模型內部的數字，常有數十億個，在訓練期間調整。模型知道的一切都住在這些數字裡，也稱權重（weights）。

訓練（Training）

設定模型參數的過程：讓模型接觸大量文本，並調整參數以改善下一 token 預測。

推論（Inference）

執行訓練好的模型以產生輸出，每次向模型供應商（model provider）發出請求時都會發生。參數維持不變。

推理力度（Effort）

控制模型回答前做多少推理的旋鈕。力度越高，花掉越多輸出 token，換取攻克難題的更好機會。

Token

模型讀寫的原子單位。大小約略是一個詞，但不完全相等。脈絡視窗（context window）的大小、成本與延遲都以 token 計算。

下一 token 預測（Next-token prediction）

模型實際在做的事。從脈絡取樣一個下一 token，附加上去，再跑一次。這是它唯一的運作方式。

非決定性（Non-determinism）

同樣的輸入可能產生不同的輸出。這既來自模型生成文字的方式，也來自供應商如何處理請求。

模型供應商（Model provider）

為推論提供模型的一方。通常是遠端服務（Anthropic、OpenAI、Google），也可以是本機（Ollama、llama.cpp）。

工具鏈（Harness）

模型之外、把模型變成代理（agent）的一切：工具、系統提示（system prompt）、脈絡視窗管理、權限、hook。

模型供應商請求（Model provider request）

從工具鏈到模型供應商的一次來回。工具鏈送出脈絡，供應商回傳一個回應。

輸入 token（Input tokens）

工具鏈在每次模型供應商請求中送出的 token。計費費率低於輸出 token。

輸出 token（Output tokens）

模型生成並回傳的 token。計費費率高於輸入 token，因為產出它們耗費更多算力。

前綴快取（Prefix cache）

供應商端的儲存，讓連續請求跳過重複處理共享的前綴，並以較低費率計算那些 token。

快取 token（Cache tokens）

供應商透過前綴快取、從先前請求快取住的輸入 token，計費費率低了許多。

工作階段、脈絡視窗與輪次（Sessions, Context Windows & Turns）

8 個條目

無狀態（Stateless）

不把資訊帶到後續。模型跨請求是無狀態的；代理跨工作階段（session）預設也是無狀態的。

脈絡（Context）

代理現在能取用的相關資訊，也就是代理所知、與任務相關的部分。

脈絡視窗（Context window）

模型在每次模型供應商請求中看到的全部內容。有限、因模型而異，是模型感知外界的唯一介面。

有狀態（Stateful）

把資訊帶到後續。工作階段跨輪次是有狀態的；代理可以透過記憶系統（memory system）做到跨工作階段有狀態。

代理（Agent）

以工具、系統提示（system prompt）與脈絡視窗裝備起來的模型，能和使用者一來一往。是動起來的模型。

系統提示（System prompt）

工具鏈加在每次模型供應商請求最前面的指令，是代理的常設任務簡報。通常在一個工作階段內保持穩定。

工作階段（Session）

與代理互動的一段有界執行。從空白開始、逐步累積，在清除、關閉或壓縮成新的工作階段時結束。

輪次（Turn）

一則使用者訊息，加上代理回應時所做的一切，直到把控制權交還使用者。其中包含一次或多次模型供應商請求。

工具與環境（Tools & Environment）

10 個條目

環境（Environment）

代理所作用的世界：工具鏈之外的一切，代理透過工具結果感知它，透過工具呼叫改變它。

檔案系統（Filesystem）

代理讀取、寫入與執行所在的檔案與目錄樹，是寫程式代理的預設環境。

工具（Tool）

工具鏈開放給代理呼叫的函式：Read、Write、Bash、Search。代理藉此感知並作用於環境。

工具呼叫（Tool call）

模型的輸出，指名某個工具及其引數，本身只是結構化文字。工具鏈必須讀取並執行它。

工具結果（Tool result）

工具鏈執行工具呼叫後送回的內容：檔案內容、輸出或錯誤。這是代理看見環境的唯一途徑。

MCP

把外部工具伺服器接上工具鏈的協定，讓代理取得工具鏈內建以外的工具。

權限請求（Permission request）

工具鏈在執行未預先核准的工具呼叫前，向使用者顯示的請求。這是把人放進迴路的機制。

權限模式（Permission mode）

代理模式中負責權限管制的那一部分：哪些工具呼叫會觸發權限請求，哪些會自動執行。

代理模式（Agent mode）

一組預設，把權限模式與注入系統提示的行為指令綁在一起。可以在工作階段中途切換。

沙箱（Sandbox）

代理在其內部執行的隔離環境：容器、虛擬機或受限的 shell。它限制代理行動的影響半徑（blast radius）。

失敗模式（Failure Modes）

9 個條目

諂媚（Sycophancy）

信心十足地迎合使用者的模型輸出。成因是訓練把模型塑造成偏好人類喜歡的答案，包括附和。

幻覺（Hallucination）

信心十足卻錯誤的模型輸出。有兩種：事實性（憑空捏造事實），以及忠實性（沒有忠於已載入的脈絡）。

參數知識（Parametric knowledge）

模型從訓練得來的知識，存放在參數中。在訓練時凍結。對應於脈絡知識（contextual knowledge）。

知識截止（Knowledge cutoff）

超過這個日期，模型就沒有參數知識。截止後才出現的函式庫與 API 是捏造陷阱，除非載入文件。

脈絡知識（Contextual knowledge）

代理現在能直接從脈絡讀到的事實。對應於參數知識。

注意力關係（Attention relationship）

兩個 token 之間的配對：有意義的配對彼此影響，比不相關的配對更多。N 個 token 的脈絡約有 N² 個這種配對。

注意力預算（Attention budget）

每個 token 能往外分配到脈絡其餘部分的影響力有限。額度以單一 token 計算，脈絡變長也不會增加。

注意力衰減（Attention degradation）

工作階段變長時，每個 token 的注意力預算攤到更多競爭者上，有意義關係上的訊號因此縮小。

聰明區（Smart zone）

工作階段初期，代理敏銳而專注。隨著工作階段變長，它漂進笨區：更馬虎、更健忘、更多錯誤。

交接（Handoffs）

9 個條目

清除（Clearing）

結束目前的工作階段，另起一個新的。下一則訊息從空白的工作階段與空白的脈絡視窗開始。

交接（Handoff）

把代理的脈絡從一個工作階段轉移到另一個，且沒有回頭路。承載機制不一：產出物、壓縮，或其他方式。

一手來源（Primary source）

事物本身：程式碼、對話紀錄、原始資料。完整且具權威性，但載入脈絡的代價高。

二手來源（Secondary source）

對一手來源的轉述，隔了一層：摘要、文件、壓縮摘要。載入便宜，但本質上會失真。

交接產出物（Handoff artifact）

用作交接承載機制的文件，由一個工作階段寫下，供另一個工作階段閱讀。

規格（Spec）

描述一件橫跨多個工作階段的工作的交接產出物：要建什麼，而不是每個工作階段怎麼做自己負責的那一份。由票（ticket）組成。

票（ticket）

界定一個工作階段範圍的交接產出物。可獨立存在，也可掛在規格之下。可以阻擋同層的票，也可能受同層的票阻擋。

壓縮（Compaction）

在記憶體內完成的交接：前一個工作階段的歷史摘要成新工作階段的起點。有損：用細節換取餘裕。

自動壓縮（Autocompact）

脈絡視窗接近全滿時，由工具鏈自動觸發的壓縮。

記憶與引導（Memory and Steering）

6 個條目

記憶系統（Memory system）

試圖讓代理跨工作階段有狀態的系統，做法是持久化到環境，並在工作階段開始時重新載入。

AGENTS.md

存在於環境中的檔案，工具鏈在工作階段開始時把它載入脈絡視窗。它是專案對代理的常設任務簡報。

漸進式揭露（Progressive disclosure）

只載入代理現在需要的脈絡，其餘的用脈絡指標（context pointer）標示，需要時再拉進來。概念借自 UI 設計。

脈絡指標（Context pointer）

一份文件中的提及，指向另一份文件，讓代理只在任務需要時才把它拉進脈絡。

Skill

打包成一個單位的可教能力，平時留在脈絡視窗外，直到脈絡指標為了眼前任務把它拉進來。

子代理（Subagent）

由另一個代理透過工具呼叫啟動的代理。在自己的工作階段中執行，回報單一工具結果。無法再啟動子代理。

工作模式（Patterns of Work）

13 個條目

人為介入（Human-in-the-loop）

一種工作模式：一個或多個人類在工作階段中與代理並肩作業，即時審查、導正或協作。

AFK

一種工作模式：使用者啟動工作階段後離開，讓代理無人看管地執行（away from keyboard）。

自動化檢查（Automated check）

在環境中執行的確定性驗證：測試、型別檢查、lint、建置、pre-commit hook。只有通過或失敗，不做判斷。

自動化審查（Automated review）

由一個代理審查另一個代理的成果，常用不同的模型或系統提示。非決定性：它會形成判斷。

人為審查（Human review）

使用者閱讀代理產出的程式碼，並據此形成判斷。讀 diff 算數；只讀摘要不算。

氛圍編碼（Vibe coding）

一種工作模式：使用者不經人為審查就接受代理的程式碼。使用者把 diff 當成看不透的黑箱。

設計概念（Design concept）

對要建什麼的共同理解，存在於使用者與代理之間，但獨立於任何產出物。

盤問（Grilling）

發展設計概念的一種技巧：代理以蘇格拉底式提問訪談使用者，一次一個決策。

原型製作（Prototyping）

對話的保真度太低、需要一個具體產出物才能討論時，先請代理做一個粗略可用的版本。

開發者體驗（DX）

開發者體驗：程式碼庫與其工具鏈讓人類做好工作的容易程度，包含文件、回饋速度、錯誤呈現。

代理體驗（AX）

代理體驗：環境為代理提供的條件有多好，讓代理能把工作做好，包含檢查、架構，以及不必花脈絡就能取得的資訊。

軟體工廠（Software factory）

一種工作系統：由觸發器而非人類啟動代理工作階段，讓更多工作以 AFK 執行，並把 HITL 時間留給真正需要的地方。

暗工廠（Dark factory）

一個程式碼庫，或其中一部分，由軟體工廠寫程式碼，且永遠沒有人審查。
